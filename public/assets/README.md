# 에셋 규격

여기에 모델을 넣으면 코드로 만들던 형태가 그 모델로 바뀝니다.
넣지 않은 것은 계속 코드로 만듭니다 — **하나씩 갈아끼울 수 있습니다.**

## 넣는 법

1. 모델을 `.glb` 또는 `.gltf` 로 내보내 이 폴더 아래에 둡니다
2. `manifest.json` 에 이름과 경로를 적습니다
3. 새로고침

```json
{
  "fill/danmuji": "fill/danmuji.glb",
  "char/customer": "char/customer.glb",
  "station/stove": "station/stove.glb"
}
```

`manifest.json` 이 없으면 전부 코드로 만듭니다. 그게 기본 상태입니다.

## 공통 규칙

- **단위는 미터.** 사람 키는 약 2.13m, 눈은 y 1.82 입니다 (머리가 큰 만화 비율)
- **정면은 +z**, 위는 +y (three.js 기본)
- 파일 하나에 씬 하나. 카메라·조명은 넣지 마세요 (무시됩니다)
- 재질은 자유롭지만, 게임 전체가 플랫한 톤이라 거친 반사는 튑니다

## 원점을 어디 두는가

| 종류 | 원점 |
|---|---|
| `fill/*` | 조각 한가운데 |
| `raw/*`, `item/*` | 물건 한가운데 |
| `char/*` | **발바닥 한가운데 (y=0)** |
| `station/*` | **바닥 한가운데 (y=0)** |

원점이 틀리면 물건이 바닥에 파묻히거나 공중에 뜹니다.

## 속재료 — 길이 1로 만드세요

`fill/*` 는 **y축 방향 길이 1.0** 으로 만듭니다. 코드가 필요한 길이로 늘여 씁니다.

같은 모델이 김밥 단면(두께 0.12)과 손에 든 재료(0.44)에 **둘 다** 쓰이기 때문입니다.
덕분에 단면에서 본 모양이 손에 든 모양과 저절로 이어집니다 — 이게 재료를 구분하는 핵심 단서라 꼭 지켜주세요.

| 이름 | 단면 크기 (x × z) | 지금 형태 |
|---|---|---|
| `fill/danmuji` | 0.056 × 0.056 | 굵은 사각 |
| `fill/ham` | 0.074 × 0.040 | 넓적한 사각 |
| `fill/egg` | 0.088 × 0.043 | 아주 납작한 판 + 흰자 층 |
| `fill/crab` | 0.060 × 0.060 | 둥근 기둥, 겉만 빨강 |
| `fill/cucumber` | 0.052 × 0.061 | 사각 + 한 면만 진한 껍질 |
| `fill/spinach` | 0.086 × 0.064 | 불규칙한 뭉치 |
| `fill/carrot` | 0.111 × 0.041 | 가는 채 여러 가닥 |
| `fill/fishcake` | 0.096 × 0.053 | 물결치는 얇은 띠 |

> **색보다 형태가 먼저입니다.** 여덟 종이 전부 노랑–주황–빨강–초록 대역에 몰려 있어서,
> 적록색약에서는 어떤 색을 골라도 구분이 안 됩니다. 단면 실루엣이 서로 확실히 달라야 합니다.

## 노드 이름을 지켜야 하는 모델

아래 모델은 **코드가 부품을 직접 움직입니다.** 이름이 안 맞으면
모델은 보이는데 안 움직입니다 — 그것도 조용히. 그래서 불러올 때 콘솔에 빠진 이름을 찍어줍니다.

> **눈은 반드시 y = 1.82 에 두세요.** 플레이어 카메라가 그 높이에 있습니다.
> 어긋나면 마주 봤을 때 한쪽이 상대를 내려다보게 됩니다.
> 전체 키는 약 2.13m — 머리가 큰 만화 비율이라 실제 사람보다 큽니다.

### `char/customer`, `char/avatar`

| 노드 | 코드가 하는 일 |
|---|---|
| `legL` `legR` | 걸을 때 x축으로 앞뒤 회전. **엉덩이(y≈0.42)를 회전 중심으로** |
| `armL` `armR` | 팔 흔들기. **어깨(y≈1.31)를 회전 중심으로**. 물건 들면 앞으로 모음 |
| `torso` | 빗자루에 맞으면 emissive 로 빨갛게 번쩍임 |
| `head` | 예약 |
| `browL` `browR` | 표정. z축 회전 + y 이동 |
| `eyeL` `eyeR` | 표정. y 배율로 눈 가늘게 |
| `mouth` | 표정. z축 180° 뒤집기로 웃음↔찡그림, x/y 배율 |

**회전 중심이 핵심입니다.** 다리 메시의 원점이 발끝에 있으면 발끝을 축으로 빙글빙글 돕니다.
Blender 라면 각 부품의 오리진을 관절 위치로 옮겨주세요.

입은 **반원 호(∪ 모양)** 로 만들어 주세요. 코드가 z축으로 뒤집어 찡그린 입을 만듭니다.

### 그 밖

| 모델 | 노드 | 쓰임 |
|---|---|---|
| `station/cooker` | `lid` | 취사 중 들썩임 |
| `item/knife` | 파일 전체 | 도마에서 써는 동안 좌우로 움직임 |
| `station/pot` | `water` | 끓을 때 y 배율로 출렁임 |
| `item/rice` | `water` | 씻을 때 보였다 안 보였다 |

## 파일로 대체할 수 없는 것

**김밥 단면은 통짜 모델로 못 만듭니다.** 속재료 8종 중 최대 6종 조합이라
경우의 수가 수백 가지고, 주문에 따라 매번 다르게 조립됩니다.

대신 `fill/*` 조각만 만들어 주시면 코드가 알아서 단면을 짭니다.

같은 이유로 이것들도 코드가 맡습니다 — 모델을 넣어도 무시됩니다.

- 김밥 단면 배치 (`rollFace`)
- 조립대 위 재료 늘어놓기
- 손님 소품 14종 (이모지별 백팩·헬멧·수염 등)
- 충돌 상자, 상호작용 판정, 머리 위 이름표

`char/customer` 모델을 넣으면 **소품은 코드가 안 붙입니다.** 모델이 이미 들고 있다고 봅니다.
손님 종류별로 다르게 하시려면 지금은 코드(`accessorize`)를 고쳐야 합니다.

## 확인하는 법

브라우저 콘솔을 보세요.

```
[assets] 모델 3개를 코드 대신 쓴다: fill/danmuji, fill/ham, char/customer
[assets] char/customer — 노드가 없다: browL, browR
[assets] fill/egg — 크기가 많이 다르다 (x 축). 규격 0.09 × 1.00 × 0.04 · 받은 것 0.31 × 1.00 × 0.04
```

크기 경고는 막지 않습니다 — 일부러 다르게 했다면 무시하세요.
노드 경고는 그 동작이 실제로 죽었다는 뜻이니 고쳐야 합니다.

전체 이름 목록과 규격은 `public/js/assets.js` 의 `CONTRACT` 에 있습니다.

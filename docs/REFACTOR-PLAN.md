# 동작 보존 리팩토링 계획

상태: **구현·검증 완료, Gate 2 승인** (2026-09-10, 사용자: “커밋 푸시해줘”)

목표: 반복 코드와 여러 곳에 흩어진 하드코딩을 함수·의미별 설정 모듈로
정리하고, 확인 가능한 반복 연산을 줄인다. 기능·그래픽·네트워크 동작은 유지한다.
규모: **large** — 브라우저, 서버, 공유 규칙, 검증 도구에 걸친 변경.

## 현재 상태와 기준선

- 기존 변경이 많은 작업 폴더다. 관련 없는 파일을 되돌리거나 일괄 커밋하지 않는다.
- 9월 8일 누락되었던 `public/assets/manifest.json`과 게임 에셋들은 9월 9일
  재확인 시 존재한다. manifest의 **56개 항목 모두 파일 존재**를 확인했다.
  이 진단 단계에서는 복원/교체하지 않았다. 별도 preview.html/png는 아직 삭제 상태다.
- 최신 `npm test`: smoke 단계를 통과한 뒤 Node 테스트에서 실패한다.
- Node 테스트 4개 파일: **34개 중 33개 통과, 1개 실패**.
  실패 위치: `test/server.integration.test.mjs:170`.
  `room:create` 응답 직후 `s.lastState.phase`를 읽지만, 서버는 응답을 보낸 뒤
  `state`를 전달한다. 첫 상태가 null인 기간을 기다리지 못하는 테스트 문제다.
- 기존 `artifacts/release-qa/report.json`: WASD 보행 단계 timeout, FAIL.
  격리 브라우저 진단으로 테스트의 상태 대기 경쟁을 확인했다.
  동료의 paused=false만 기다릴 때 방장의 KeyW 이벤트에는 paused=true가 기록됐다.
  이벤트 대상은 BODY, document.hasFocus()=true였으므로 이 재현은 포커스 문제가 아니다.
  이후 방장/동료 모두 paused=false를 기다리자 같은 W 입력으로
  X=-1.6 → -2.61916까지 정상 이동했고 위치 보정 version은 0이었다.
  이는 원인 분리 진단이며, 기존 전체 브라우저 QA가 통과한 것은 아니다.

## 범위와 완료 조건

단일 모델의 조형 좌표까지 하나의 거대한 constants 파일로 옮기지 않는다.
공유 의미가 있는 값은 공용 정의로, 특정 모델에만 속한 값은 해당 모델의
지역 설정으로 관리한다. 새 의존성, 게임 규칙 변경, 캐릭터 재디자인은 범위 밖이다.

위 작업별 중복 소비 지점이 같은 정의를 사용하고, 수치·동작·외형이 유지되며,
관련 테스트와 최종 전체 검증이 실제 통과해야 완료다. 에셋 누락이나
기존 실패가 남아 있으면 부분 통과를 전체 완료로 간주하지 않는다.

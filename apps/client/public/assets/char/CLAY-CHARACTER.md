# Clay character v2

Original, texture-free models generated by `tools/blender/build-clay-character-assets.py`.
The older PEAK conversion and modular character generators are not used by this set.

## Build

From the repository root in PowerShell:

```powershell
& 'C:\Program Files\Blender Foundation\Blender 5.2\blender.exe' --background --python tools/blender/build-clay-character-assets.py
npm test
node tools/character-preview-qa.cjs
```

The visual test uses local Chrome and a bundled Playwright install. Override
`PLAYWRIGHT_PATH` with a local Playwright module path and `QA_URL` if needed.
It creates a disposable local test room and disconnects both test players.
Do not run this harness against a production game server.

## Coordinate / attachment contract

- Units: metres, +Y up, face +Z, origin at the centre of the feet.
- `base.glb`: `rig`, `body`, `head`, `armL/R`, `legL/R`.
- Fallback clothing: `baseTop`, `baseBottom`, `baseSleeveL/R`, `basePantsL/R`.
- `top/*.glb`: `garmentBody`, `sleeveL/R` in the common foot coordinate system.
- `bottom/*.glb`: `waist`, `trouserL/R` in the common foot coordinate system.
- `Object3D.attach` moves garment sockets under each limb, preserving transforms.
- Animation multiplies the saved rest quaternion, never overwrites bind rotation.
- Hair already includes the 0.875 head reduction about Y=1.76. Face geometry uses
  the same factor in `world.js`; do not scale the hair a second time at runtime.
- Arm pivot: X=±0.282, Y=1.255; hip pivot: X=±0.148, Y=0.73.

## Material slots / customization

`skin`, `shoe`, `custom`, and `customShade` are recoloured per instance.
Linen, stitching, soles and buttons keep their authored colours.
All surfaces use a roughness of 0.86 and zero metalness. No external textures.

Look fields: `h/hc` hair/style colour, `f` face accessory, `e` expression,
`t/tc` top/style colour, `b/bc` bottom/style colour, `sc` skin, `shc` shoe colour.
Old saved looks without new fields default safely to index zero.

## Verification

Visuals are assembled by the game's own `previewBody`, not a separate render model.
The harness saves front/side/back/walk/holding and in-game screenshots under
`artifacts/character-qa/`; it checks all 162 garment combinations, rest poses,
save/reload, responsive overflow and two-client skin/clothing synchronization.
There is no committed visual baseline: automated pixel regression is inconclusive.
Screenshots must be inspected by a human/visual reviewer for intersections.
